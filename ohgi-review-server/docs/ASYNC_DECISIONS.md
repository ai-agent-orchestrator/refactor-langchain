# 어디까지 비동기로 바꾸나요?

추천 기준은 함수 이름이 아니라 **이벤트 루프가 무엇을 기다리는가**입니다.

| 작업 | 선택 | 이유 |
|---|---|---|
| 모델·구조화 출력 호출 | `await ...ainvoke()` | HTTP 응답 대기 중 다른 요청 처리 |
| 그래프 실행 | `await graph.ainvoke()` | 내부 노드의 비동기 호출 연결 |
| 토큰 스트리밍 | `async for ...astream()` | 생성되는 조각을 차례대로 전달 |
| 원격 임베딩 | 가능하면 네이티브 async | 네트워크 대기 분리 |
| 동기 Chroma·문서 분할·로컬 임베딩 | `to_thread.run_sync` 등 작업 스레드 | async def로 감싸기만 해서는 비동기가 되지 않음 |
| 큰 CPU 계산 | 운영에서는 프로세스·작업 큐도 검토 | 스레드는 CPU 처리량 개선을 보장하지 않음 |
| Pydantic 검증·JSON 변환·짧은 조건 분기 | 동기 함수 | 짧은 계산에 비동기 대기가 없음 |
| 기존 리뷰 등록·조회 라우터 | 원본 `def` 유지 | FastAPI가 작업 스레드에서 실행; 계층 유지 요구 준수 |
| 모델·체인·그래프 생성 | lifespan에서 프로세스당 한 번 | 비싼 객체 재사용 |
| 실행 카운터·스트림 누적 상태 | 요청별로 분리 | 동시 요청 데이터가 섞이지 않도록 함 |

`async def f(): sync_model.invoke()`는 이벤트 루프를 막습니다. `await asyncio.to_thread(sync_model.invoke, ...)`는 이행용 어댑터가 될 수 있지만, 취소·토큰 스트리밍·스레드 수 관리까지 고려하면 네이티브 `ainvoke/astream`이 우선입니다. 스레드로 넘긴 동기 함수는 await가 취소되어도 이미 시작한 작업이 즉시 멈춘다고 보장할 수 없습니다.

따라서 **외부 I/O 실행 경로는 비동기로 통일하고 짧은 순수 계산은 동기로 유지**합니다. 테스트에서는 동시에 다른 코루틴이 진행되는지와 실제 Uvicorn 요청의 MainThread 로그를 함께 확인합니다. MainThread라는 이름만으로 내부에 블로킹 호출이 없다는 사실까지 증명되는 것은 아닙니다.
